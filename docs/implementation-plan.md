# 海淀GEP数据工作台实施计划

目标：把实施手册中的数据接入、缺数处理、校验及发布准备做成可运行CLI，并建立GitHub代码环境。交互页面和全GEP算法属于PRD设计，当前原型演示农产品和水产的输入、人工选择及复算。

架构：Python标准库实现本地数据与审核流程；ModelScope同步使用锁定版本的官方SDK。原件保存在数据目录，代码、环境、模板与方法卡保存在独立Git仓库。凭据仅通过环境或进程内传入。

用户已授权直接修改Overleaf、建立GitHub仓库、在发布前检验数据并最后上传指定ModelScope；执行时不请求重复批准。

1. 编写缺失值、非有限数、重复主键、未审核输入、历史覆盖和上传杂文件检查。
2. 实现check/build/fetch/example/resolve/approve/release/verify-release/upload命令，固定输入及产物。
3. 提供Python环境、固定SDK版本、Docker入口和完整双科目演示，验证安装与运行。
4. 重写1.2、2.1、3.2，增加统计品类登记、遥感按需使用、操作手册、PRD流程与案例。
5. 生成明示范围的参考数据发布包：已复核统计事实、缺项、口径问题、字典、来源和方法。受限原件留本地；上传包不含凭据、未核实估计或虚构完整GEP。
6. 验证文档、代码、算例和发布清单后同步GitHub与Overleaf；最后上传冻结包并回下载逐文件比对。

重点失败情形：空白伪零、鱼收获kg/t混用、层级统计重复累计、待审核估计自动入总账、跨年、历史被覆盖、发布目录混入本地原件或凭据、重发覆盖远端。全GEP缺口记录在数据卡；参考包通过检查不表示全科目就绪。
