# 海淀区 GEP Demo：全量智能体补充、右侧抽屉与事件流动效果设计

## 1. 背景与目标

当前任务画布已经显示年度 GEP、三大类和 22 个标准科目，并具备持久化补充队列、节点证据和人工审核基础。但现有行为与最新确认的演示目标仍有三处差距：

1. 节点事件只触发卡片光晕，没有沿依赖连线移动的“水流”效果。
2. 点击科目后，细节图追加到总图下方，用户容易看不到新内容。
3. 补充任务需要人工逐节点发起；初稿画完后，大部分节点长期停在“待智能体补充”。

本次改动的目标是：任务图建立后自动完成全量、可恢复的智能体补充流程；每个待处理节点最终进入“智能体已补充·待审核”或“待人工介入”；真实任务事件沿对应连线显示短暂流动效果；所有科目详情和数据证据改在右侧抽屉内查看。

本设计遵守 GB/T 46869—2025 的核算边界和现有“智能体生成候选、人工审核、确定性公式计算”分工。模型输出不得自动成为正式核算值。

### 1.1 已确认的产品决定

- 点击科目或数据节点时使用右侧抽屉，不再在总图下方展开详情。
- 创建任务并完成初始画图后，系统自动处理全部待补节点，不要求用户逐项点击。
- 自动处理结束后，每个相关节点必须是待审核、待人工介入、已审核或正在处理等明确状态，不允许无故长期停留在初始状态。
- 计算和补充过程中的流动动画必须由已持久化事件驱动，不得用循环动画冒充真实执行。
- 使用 DeepSeek API 完成真实联调；密钥不得写入仓库、前端、数据库、事件载荷、截图或日志。

### 1.2 与既有实施方案的关系

`overleaf/implementation/main.tex` 第 7 章原先规定“点击科目后在下方展开该科目的细节图”。用户在 2026-09-28 明确将该交互改为右侧抽屉。本设计中的右侧抽屉是最新要求，覆盖该处旧表述；其他关于总图层级、科目细节、证据审核、状态机和事件真实性的要求继续有效。

## 2. 方案选择

采用“服务端直接接入 DeepSeek，复用现有持久化补充队列”的方案。

- 保留 `SupplementWorkflow` 边界、SQLite 补充作业、独立 worker、节点版本冲突保护和事件序列。
- 新增 `DeepSeekWorkflow`，与现有 `DifyWorkflow` 并列，通过环境变量选择提供方。
- 浏览器不直接访问模型服务；所有请求由 worker 发起。
- Dify 适配器继续保留，避免破坏既有部署能力，但本轮联调使用 DeepSeek 适配器。

不采用浏览器直连方案，因为它会暴露 API 密钥；不强制部署 Dify，因为本轮只需验证节点补充链路，额外编排层会增加部署和排障成本。

## 3. 总体架构

```text
任务创建 API
  ├─ 写入三大类、22 科目及必需输入节点
  ├─ 写入 task.created / graph.* 事件
  └─ 幂等创建自动补充作业
          │
          ▼
持久化 supplement_jobs 队列
          │
          ▼
单 worker 顺序认领作业
  ├─ 本地证据解析器：读取准入数据和来源定位
  ├─ DeepSeekWorkflow：只整理证据、解释口径并输出结构化结果
  └─ 业务校验器：验证结果类型、字段、来源定位和 SHA-256
          │
          ├─ candidate → 智能体已补充·待审核
          └─ manual_required → 待人工介入
          │
          ▼
节点、作业和事件原子落库
          │
          ▼
Web 轮询事件 → SVG 连线流动 → 节点状态更新 → 右侧抽屉展示
```

第一版继续使用单 worker 顺序执行。这样能控制模型调用速率、让事件流向在 Demo 中清晰可见，并避免 SQLite 多写者竞争。队列本身保持可恢复，后续如需并发可在不改变前端协议的情况下扩展。

## 4. 自动补充流程

### 4.1 两阶段调度

自动补充按两阶段执行：

1. **科目适用性阶段**：处理 22 个 indicator 节点，依据本地资料判断可形成“适用”“不适用”“已核实为零”的待审提案，或因证据不足转为待人工介入。
2. **输入字段阶段**：仅为“适用”候选所需的 input 节点执行取数与说明生成。已有值且处于待审核/已审核的节点不重复调用模型；不适用或已核实为零的分支暂停字段补充。

由于科目适用性仍需人工审核，首轮 Demo 允许第二阶段对模板中已经明确登记的必需输入先行排队，但其结果不会绕过父科目审核进入快照。这样既能展示全量处理，又不把模型判断当作正式适用性结论。

### 4.2 幂等与恢复

- 任务创建后由服务端统一调用 `enqueue_all_supplements(task_id)`，不依赖浏览器保持在线。
- 自动作业幂等键由任务 ID、节点 ID、节点版本和自动调度版本构成。
- 重复打开任务、页面刷新或重复调用批量接口不会产生重复作业。
- worker 中断后沿用现有超时重排机制。
- 人工在模型运行期间修改节点时，迟到结果进入 `stale`，不得覆盖新版本。
- 对历史任务提供显式“继续自动补充”操作，只补齐当前仍可调度的节点。

### 4.3 状态机

页面统一显示以下状态：

| 服务状态 | 页面文案 | 终态 |
|---|---|---|
| `awaiting_agent` | 待智能体补充 | 否 |
| `agent_queued` | 智能体排队中 | 否 |
| `agent_running` | 智能体补充中 | 否 |
| `candidate_ready` + `pending_review` | 智能体已补充·待审核 | 是，等待人工 |
| `manual_required` | 待人工介入 | 是，等待人工 |
| `agent_failed` | 补充失败·可重试 | 是，等待操作 |
| `approved` | 审核通过 | 是 |
| `returned` | 退回重查 | 是，等待重新调度 |

作业失败与业务上缺少可信来源必须区分：网络、限流或无效响应属于 `agent_failed`；资料不存在、证据不足、口径冲突或权限受限属于 `manual_required`。前者允许重试，后者要求上传材料、补充依据或人工作出适用性结论。

## 5. DeepSeek 接入与证据边界

### 5.1 运行配置

新增以下运行时环境变量：

- `SUPPLEMENT_PROVIDER=deepseek|dify|none`
- `DEEPSEEK_API_BASE_URL`，默认 `https://api.deepseek.com`
- `DEEPSEEK_API_KEY`
- `DEEPSEEK_MODEL`，默认 `deepseek-flash`，保持可配置
- `DEEPSEEK_TIMEOUT_SECONDS`

宿主机密钥保存在运行目录下权限为 `0600` 的环境文件，通过 Compose 运行时注入。应用错误信息只记录提供方、HTTP 状态类别和内部作业 ID，不记录请求头、密钥或完整提示词。

### 5.2 输入约束

模型不能自行浏览互联网或读取任意本地文件。worker 先由本地证据解析器为工作单附加允许使用的结构化资料摘要，包括来源 ID、文件路径、年度、区域、表号页码、字段、原始片段和文件 SHA-256。DeepSeek 只对这份证据包进行：

- 科目适用性说明；
- 字段提取和单位说明；
- 口径、范围与待核查问题总结；
- 在无充分证据时返回人工介入原因。

不得要求模型凭常识估计本地数值，不得把模型自身知识当作来源。

### 5.3 结构化输出

DeepSeek 使用 JSON 输出，返回三种互斥结果之一。数值输入候选为：

```json
{
  "outcome": "candidate",
  "value": 2935.1,
  "unit": "t/a",
  "explanation": "...",
  "evidence": {
    "source_id": "...",
    "source_type": "observed",
    "locator": "...",
    "source_sha256": "...",
    "license_or_access": "...",
    "tool_run_id": "...",
    "extracted_fragment": "..."
  }
}
```

科目适用性候选为：

```json
{
  "outcome": "applicability_candidate",
  "applicability_status": "applicable",
  "explanation": "...",
  "evidence": {
    "source_id": "...",
    "source_type": "observed",
    "locator": "...",
    "source_sha256": "...",
    "license_or_access": "...",
    "tool_run_id": "...",
    "extracted_fragment": "..."
  }
}
```

人工介入结果为：

```json
{
  "outcome": "manual_required",
  "reason_code": "source_missing",
  "explanation": "已检查哪些资料、缺少什么、人工下一步应提供什么"
}
```

后端不信任模型输出。数值 candidate 必须通过现有数值、单位、证据字段、来源哈希和节点版本校验；applicability candidate 只接受 `applicable`、`not_applicable` 或 `verified_zero`，并使用同样的证据校验。两类候选都进入人工待审，不直接改变正式适用性或正式输入。模型引用的来源 ID 必须存在于本次工作单的允许来源集合。`manual_required` 只保存原因和已检查范围，不产生值。

## 6. 右侧抽屉交互

### 6.1 抽屉容器

- 桌面端抽屉固定在应用右侧，建议宽度 420--480 px，高度覆盖当前内容区。
- 抽屉打开时画布保持原滚动、缩放和折叠状态；可适度缩小可视宽度，但不重绘到页面下方。
- 点击遮罩、关闭按钮或按 Escape 关闭；焦点进入抽屉并在关闭后返回原节点。
- 窄屏下抽屉改为接近全屏的右侧滑层。

### 6.2 两类内容

**科目抽屉**展示科目说明、对象/产品目录和鱼骨式字段列表。点击字段时在同一抽屉中切换到证据视图，并提供返回科目详情的面包屑，不再打开第二个叠加弹窗。

**数据节点抽屉**展示状态、候选值、智能体补充说明、来源定位、执行记录、方法与范围，以及审核通过、人工纠正、退回重查、补材料和重试动作。

原 `detail-board` 和 `evidence-dialog` 的内容逻辑迁入统一抽屉；不保留画布下方详情区，避免两套交互同时存在。

## 7. 连线流动效果

### 7.1 绘制方式

当前连接线由 CSS 边框和伪元素组成，无法可靠地沿路径动画。总图改为在节点层下方放置 SVG edge layer，根据根节点、类别头和科目节点的实际布局计算路径。路径具有稳定的 `data-edge` 标识：

- `root -> category`
- `category -> indicator`
- 抽屉内 `indicator -> object/product -> input`

窗口尺寸、抽屉开合、缩放和折叠变化后重新计算路径，但这些视图变化不写入核算图版本。

### 7.2 事件驱动动画

- `task.created` 或图构建事件按根节点、三大类、科目的顺序播放一次初稿展开。
- `supplement.queued`、`supplement.running`、`supplement.candidate_persisted`、`supplement.manual_required` 和 `supplement.failed` 只动画对应节点的依赖路径。
- SVG 使用短虚线/渐变段沿路径移动，持续约 0.8--1.2 秒；节点同时得到轻量脉冲，但不永久闪烁。
- 系统开启减少动态效果时停用路径移动，只用颜色变化表达状态。
- 历史事件恢复只更新最终状态；除非用户主动选择“回放”，不在每次刷新时重复播放全部动画。

## 8. API 与事件变化

保留现有单节点补充接口，并新增批量调度能力：

- `POST /tasks/{id}/supplements:auto`：幂等调度所有当前可处理节点；任务创建时由服务内部直接调用同一领域方法。
- 返回排队数、跳过数及按原因分组的跳过摘要。

新增或规范事件：

- `graph.initialized`
- `supplement.auto_enqueued`
- `supplement.queued`
- `supplement.running`
- `supplement.candidate_persisted`
- `supplement.manual_required`
- `supplement.failed`
- `supplement.stale`

事件载荷只保存状态所需的节点版本、作业 ID、原因码和证据引用 ID，不保存 API Key、Authorization、完整提示词或模型原始响应。

## 9. 错误处理

- 401/403：作业标为失败，页面提示模型凭据不可用；不回显服务端响应正文。
- 429/5xx/超时：作业标为可重试失败，保留尝试次数；第一版由人工触发重试，避免无限调用产生费用。
- 空内容、截断 JSON、字段类型错误：按无效模型响应处理，不写入候选值。
- 引用不在允许来源集合、SHA-256 不匹配或数值非有限：拒绝候选并记录安全校验失败。
- 无证据或口径冲突：进入 `manual_required`，不是系统错误。
- 浏览器断线：重新读取图快照并从最后事件序号补拉，抽屉可恢复当前选中节点。

## 10. 测试与验收

### 10.1 自动化测试

- DeepSeek 适配器：请求格式、JSON 输出、超时和 HTTP 错误脱敏、两种结果解析、密钥不出现在异常中。
- 证据校验：拒绝未知来源、错误哈希、缺字段、非有限值和截断 JSON。
- 自动调度：新任务自动排队、重复调度幂等、已有候选/已审核节点跳过、人工修订后的迟到结果变 stale。
- 状态机：candidate、manual_required、failed 和重试均产生正确节点状态与事件。
- Web 契约：页面不再包含下方 `detail-board`；存在统一右侧抽屉、焦点恢复、移动端样式和状态文案。
- 动画：事件能定位正确 edge；无事件不播放；减少动态效果下禁用位移动画。

### 10.2 真实联调

使用运行时注入的 DeepSeek 密钥，对独立测试数据库创建任务，至少验证：

1. 一条有本地证据的节点能形成结构化待审核候选；
2. 一条无可信来源的节点进入待人工介入；
3. 模型响应不会自动变为审核通过；
4. 页面依次显示排队、运行和终态，并沿正确连线播放流动效果；
5. 日志、SQLite、导出包和静态资源中不存在密钥。

### 10.3 部署验收

- 本地完整测试通过后构建新 release，不覆盖旧 release。
- 部署前备份运行数据库，部署后核验 API、worker、Web、历史任务恢复和新任务自动补充。
- 通过实际浏览器截图验证总图、右侧抽屉和至少一条真实事件动画后的状态。
- 保留回滚到当前 `690284f` 版本的能力。

## 11. 明确不在本次范围内

- 不让 DeepSeek 执行正式 GEP 数值计算或批准审核。
- 不用模型常识填补缺失的海淀区事实数据。
- 不实现互联网通用搜索、OCR 或任意文件浏览工具。
- 不改变三大类 22 科目的国标结构和正式快照审核闸门。
- 不把循环动画、教学值或模拟证据包装成真实智能体执行结果。
