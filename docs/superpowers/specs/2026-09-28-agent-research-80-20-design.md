# 海淀 GEP 智能体 80/20 自动化与 A1 审核设计

## 1. 目标

把当前“本地没有精确证据即待人工介入”的单一流程，升级为能够自动检索官方来源、读取本地数据、组织 AEF 空间任务、生成候选、校验证据并按风险分流的工具型智能体。

产品目标不是伪造“80% 数值已齐全”，而是让智能体完成约 80% 的检索、提取、空间处理、口径检查和缺口整理工作。人工只处理来源冲突、关键方法选择、受限材料和高影响修正。没有数据的节点显示“已自动检索·等待数据”，不再全部显示“待人工介入”，但仍诚实阻断正式核算。

## 2. 已确认的交互决定

- 采用 A1“证据优先”抽屉：结果、数据来源、自动校验，工作执行记录折叠。
- 高可信结果自动采用，不要求逐节点点击通过；默认进入整批确认池。
- 中风险候选暂停正式采用，可逐项快速复核，也可在整批确认时默认审核。
- 专家介入只用于资料权限、来源冲突、方法选择或高影响参数。
- 点击“整批确认”时显示仍未逐项审核的数量；确定后写入批量审核记录并默认审核，取消后进入逐项审核。
- 缺资料、硬冲突及方法未决节点不能被整批确认绕过。
- 自动采用只允许政府官方来源、本地准入数据和校验通过的 AEF/确定性计算；普通网页和论文只生成待复核候选。

## 3. 工作流与状态

### 3.1 工具链

每个节点工作单依次执行：

1. 搜索本地准入数据与既有证据；
2. 搜索官方来源注册表并在线验证 URL；
3. 对适用的空间字段检查 AEF 2024 VRT、64 个嵌入维度、10 m 网格、边界覆盖与标签/校准资产；
4. 生成结构化候选或结构化缺口；
5. 校验来源 ID、URL、定位、SHA-256、区域、年度、单位和方法适用性；
6. 由风险策略分为 A、B、C 或 research-gap。

DeepSeek 负责节点任务规划和生成面向用户的说明，不直接决定官方数值。工具输出和规则引擎决定值、来源身份与风险等级。

### 3.2 四种结果

| 结果 | 页面状态 | 处理 |
|---|---|---|
| A 高可信候选 | 已自动采用·待整批确认 | 进入试算输入和批量复核池 |
| B 中风险候选 | 已补充·建议复核 | 暂停正式采用，可逐项或整批确认 |
| research-gap | 已自动检索·等待数据 | 不要求立即人工操作，继续作为正式核算阻断项 |
| C 专家介入 | 需专家介入 | 补材料、定口径、处理冲突或暂缓 |

网络错误与模型错误继续单独显示为“执行失败·可重试”，不能伪装成业务缺口。

## 4. 官方来源工具

首版采用版本化官方来源注册表，而不是让模型自由采信搜索结果。注册表记录：来源 ID、政府域名、URL、年份、区域、表/页定位、许可、事实字段、单位、来源哈希或在线验证状态、适用节点及风险规则。

首批来源包括：

- 北京市园林绿化局《2024 年城市绿化资源情况》：海淀绿化覆盖面积、绿地面积、公园绿地、防护绿地、区域绿地等；
- 北京市水务局《2024 年北京市水资源公报》：海淀区用水分项；
- 北京市园林绿化局《北京市公园名录（2024 年度）》；
- 北京市生态环境局《2024 年北京市生态环境状况公报》；
- 已准入的《2025 北京海淀统计年鉴》2024 年记录。

官方来源注册表中的直接事实可成为 A 候选；需要代理变量、口径转换或与本地记录不一致时只能成为 B/C。

## 5. AEF 空间工具

AEF 年度嵌入是 64 维特征，不直接等于“绿地”标签。首版工具必须：

- 解析本地 VRT 并验证 2024 年、64 波段、10 m 分辨率、UTM 50N 和远端 COG 引用；
- 检查正式边界、训练/校准标签和可访问栅格是否齐备；
- 资产齐备时允许执行分类/回归并输出面积、空间产物、验证指标及证据哈希；
- 资产不齐备时输出 research-gap 和精确缺项，不得把官方区级绿地总量伪装成 AEF 分类结果；
- 官方绿地总量可作为 AEF 空间分配或面积勾稽依据，但属于 B 候选，直到具备独立样本验证。

当前数据只有 AEF 远端 VRT 和候选索引，尚无经确认边界、正式训练标签与完成验证的分类栅格。因此本轮交付 AEF 资产检查和空间任务入口，不能宣称已经得到正式 AEF 绿地分类成果。

## 6. 风险策略

### A：允许自动采用

- 本地准入记录与节点字段精确匹配；
- 政府官方直接事实与区域、年度、单位完全匹配；
- 确定性计算的全部输入均为 A 且公式版本已锁定；
- AEF 输出具有正式边界、独立标签、验证指标和产物哈希。

### B：建议复核

- 官方事实需要单位/口径转换；
- 官方区级总量作为空间代理或 AEF 校准目标；
- 多个可信来源存在轻微差异；
- 文献参数具有适用性说明但不是本地实测。

### C：专家介入

- 可信来源冲突且影响核算；
- 不适用/已核实为零需要业务判断；
- 受限数据需要授权；
- 方法选择会改变计量边界或重复项处理。

### research-gap

所有允许的本地和官方工具均已执行，但仍没有可用数值，且当前没有需要人工立即决策的事项。保存已搜索范围、时间、工具记录和下一数据请求。

## 7. 批量确认

新增批量审核记录，保存任务 ID、图版本、节点及其版本、风险等级、批量确认人、时间、说明和被排除的硬阻断项。

`GET /tasks/{id}/batch-review-preview` 返回：A 自动候选、B 待复核、research-gap、专家介入、失败及硬阻断数量和节点列表。

`POST /tasks/{id}/batch-reviews` 接受当前图版本和 `ignore_individual_review`：

- `true`：将当前版本的 A/B 候选批量批准，逐节点审核记录引用同一批量记录；
- `false`：不改变节点，返回逐项审核队列；
- research-gap、专家介入、失败和版本冲突永远不能被批量批准。

## 8. A1 抽屉

高可信节点首屏只显示：

1. 当前结果及“已自动采用·待整批确认”；
2. 数据来源、表页定位、来源等级和在线/哈希校验；
3. 自动校验摘要；
4. 折叠的工作执行记录；
5. “标记问题”“人工修正”。

B 节点增加一个主按钮“确认采用”；C 节点显示与原因匹配的“补充材料”“选择方法”等动作。删除“智能体如何补充”标题和大段模型自述。

任务页顶部显示 A/B/research-gap/C/失败数量和“整批确认”按钮。确认弹层明确哪些节点会被批准、哪些仍保持阻断。

## 9. 事件、恢复与迁移

新增事件：`research.started`、`source.verified`、`aef.inspected`、`research.completed`、`candidate.auto_verified`、`batch_review.previewed`、`batch_review.completed`。

旧版 `manual_required/source_missing` 节点在恢复任务时按新调度版本重新排队；来源冲突、权限和方法选择节点保留 C 状态。所有作业继续保持幂等和版本冲突保护。

## 10. 验收

- 新建和旧任务均自动进入新版研究工作流；
- 所有节点最终为 A、B、research-gap、C 或失败，不无故停留在等待状态；
- 官方绿地和水资源来源可在线验证并形成带定位的候选；
- AEF 工具如实报告资产就绪度，不伪造分类结果；
- A1 抽屉不再显示“智能体如何补充”；
- 批量确认可以批准 A/B，不能绕过硬阻断；
- 刷新和 worker 重启后状态、证据、批量审核记录与事件均可恢复；
- 密钥不进入 API、Web、数据库事件、静态资源或导出包；
- 本地、宿主机测试及真实浏览器验收通过后部署 9088，并推送 GitHub。
