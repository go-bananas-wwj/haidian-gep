# 海淀 GEP 2024 智能数据后台与自动试算设计

## 1. 状态与适用范围

- 状态：已完成会话设计，待用户审阅本文后进入实施计划。
- 核算主线：海淀区 2024 年度 GEP Demo。
- 产品原则：智能体尽可能完成数据发现、读取、空间处理、方法选择、试算和解释；人工只处理部门材料、来源冲突和会改变核算边界的业务判断。
- 用户已确认：公开数据、遥感和模型推导形成的估算值，只要明确标注“模型估算、非正式统计”，可以自动进入 Demo 试算。
- 本设计取代旧流程中“无直接事实即 research-gap”的默认行为；旧的正式核算审计约束继续保留。

## 2. 目标

1. 下载并裁剪覆盖海淀区的 2024 AlphaEarth Foundations（AEF）年度嵌入。
2. 把 AEF、MODIS NPP/ET、NASA POWER、WorldCover、DEM、统计年鉴和官方在线来源登记为可查询的数据资产。
3. 通过可复算工具生成物理量、面积、模型参数和估算候选，而不是只生成“已搜索但没有数据”的说明。
4. 由 DeepSeek 智能体选择已批准的方法、组织结构化计算计划、调用工具并解释结果；数值计算由版本化代码执行。
5. 同时支持“智能试算”和“正式核算”两套就绪度，允许 Demo 继续运行而不把估算值冒充正式统计值。
6. 科目节点只汇总下游状态，不再作为一个待取数节点进入研究队列。
7. 页面把人工工作收敛为少量、可操作的部门数据请求和业务判断。

## 3. 非目标

- 首轮不承诺生成可对外发布的正式海淀区 GEP 总值。
- 不把 AEF 64 维嵌入直接解释为绿地、NPP、径流或其他物理量。
- 不允许大模型执行任意代码、自由拼接公式或在没有证据时生成数值。
- 不把 2025-12 至 2026-05 的玄女覆盖期数据混入 2024 年度正式输入；它只保留为对照和后续变化分析资产。
- 不把大型栅格、模型文件或密钥提交到 GitHub。

## 4. 已有数据与质量边界

### 4.1 可用于 2024 试算的数据

| 资产 | 时间与粒度 | 首轮用途 | 风险等级 |
|---|---|---|---|
| AEF 年度嵌入 | 2024，10 m，64 维 | 土地/生态系统分类、面积和空间分配 | 模型估算 B |
| ESA WorldCover | 2021，10 m | AEF 弱监督伪标签、覆盖因子先验 | 模型估算 B |
| Copernicus DEM | 30 m | 坡度、坡长和地形分区 | 公开数据计算 B |
| MODIS MOD16 ET | 2024，年度累计 | 实际蒸散、蒸腾代理、气候调节输入 | 公开数据计算 B |
| MODIS MOD17 NPP | 2024，年度 | 固碳路径的 NPP 输入 | 公开数据计算 B |
| NASA POWER | 2024，单点月尺度 | 降水、温度、短波辐射代理 | 区域代理 B |
| 海淀统计年鉴 | 2024 记录 | 玉米产量等本地统计事实 | 直接事实 A |
| 北京市官方公报 | 2024，区级或市级 | 绿地、水资源、价格和参数候选 | A/B，按口径决定 |

### 4.2 已知质量限制

- 当前边界是 OSM Demo 边界，面积约 430.52 km²，不是经主管部门确认的正式边界。
- NASA POWER 是单个粗网格点，不能作为正式区级空间强迫场。
- MODIS NPP 是 NPP，不是 NEP；必须显式选择转换路径和参数。
- MODIS ET 的范围有效性已检查，但正式 QC 接受阈值仍需方法版本记录。
- WorldCover 2021 与 AEF 2024 存在三年时间差，只能用作弱监督标签。
- 玄女 1,920 份嵌入的发布清单 SHA-256 与本地抽取文件不一致，且时间为 2025-12 至 2026-05；不得替代 2024 AEF。
- 玄女土地覆盖数字类别映射尚未得到发布方确认。

这些限制不阻断智能试算，但必须进入证据账本、置信度和页面提示；它们继续阻断正式核算自动采用。

## 5. 总体架构

```text
本地文件 / 官方网页 / 2024 AEF COG
                    │
                    ▼
        数据资产登记与质量检查
                    │
                    ▼
       派生观测与空间特征生成器
                    │
                    ▼
   方法注册表 ──► 智能体计划器 ──► 安全执行器
                    │                  │
                    └────────┬─────────┘
                             ▼
                    候选值与证据账本
                             │
                 ┌───────────┴───────────┐
                 ▼                       ▼
             智能试算                正式核算闸门
```

系统分成五个职责单一的组件：

1. **数据资产登记器**：发现和登记原始/派生资产，保存时间、空间范围、单位、哈希、许可和质量。
2. **派生观测生成器**：执行裁剪、聚合、分类、单位转换和确定性计算，输出小型结构化观测。
3. **方法注册表**：保存允许使用的公式、参数要求、适用规则、风险规则和实现版本。
4. **智能体计划器**：根据目标字段查询资产和方法，返回通过 JSON Schema 校验的计算计划与解释。
5. **安全执行器与证据账本**：只执行允许的方法操作，保存完整输入、参数、代码版本、输出和不确定性。

大型栅格只在离线数据准备进程中读取；Web/API/DeepSeek只读取资产元数据、统计摘要和派生观测。

## 6. 2024 AEF 获取与分类

### 6.1 来源与裁剪

本地 `aef_index.parquet` 已筛出三个覆盖海淀 bbox 的 2024、UTM 50N 候选瓦片。获取流程必须：

1. 从 Source Cooperative 读取每个候选 TIFF 的配套 VRT；VRT 用于修正该镜像的 bottom-up 存储方向。
2. 使用 HTTP/S3 Range 读取和空间窗口裁剪，避免下载三个完整 8192×8192×64 瓦片。
3. 先合并重叠窗口，再按 OSM Demo 边界掩膜，避免重叠像素重复计数。
4. 保留原始 signed Int8 和 NoData=-128，分析时按官方规则反量化一次；禁止重复反量化。
5. 输出海淀子集 COG、VRT、资产清单、SHA-256、像元覆盖报告和来源归属信息。

输出默认位于：

```text
data/haidian_gep_2024/
├── 01_raw/remote_sensing/alphaearth_2024/
├── 02_intermediate/alphaearth_2024/
└── 03_features/alphaearth_2024/
```

原始和派生栅格由 `.gitignore` 排除；Git 只保存处理代码、清单模式、测试夹具和不含大文件的质量报告。

### 6.2 弱监督分类

首轮用 WorldCover 2021 作为伪标签训练 AEF 2024 分类器：

- 输入特征：反量化后的 A00–A63。
- 标签：WorldCover 稳定类别，剔除边界混合像元和 NoData。
- 训练样本：按类别与空间块分层抽样，限制每类样本量，避免面积较大的建成区支配模型。
- 模型：版本化 Random Forest；固定随机种子并保存参数、训练样本索引哈希和模型哈希。
- 验证：空间块隔离的留出集，不允许随机像元拆分造成空间泄漏。
- 指标：总体准确率、macro-F1、每类 precision/recall/IoU、置信度覆盖率和面积勾稽差异。

分类结果进入 Demo 自动试算的最低门槛：macro-F1 ≥ 0.70，且参与 GEP 的每个主要生态系统类别 recall ≥ 0.50。未达到门槛时仍保存产物和报告，但状态降为“建议复核”，不能自动进入试算。

官方绿地面积只用于区级面积勾稽。AEF 绿色生态系统总面积与官方绿化面积差异超过 20% 时，结果降为“建议复核”；系统不得通过强制缩放栅格来隐藏差异。

### 7.2 API

新增只读接口：

- `GET /data-assets`
- `GET /data-assets/{asset_id}`
- `GET /derived-observations?metric=&year=&region_code=`
- `GET /tasks/{task_id}/automation-summary`
- `GET /nodes/{node_id}/calculation-chain`

新增受控执行接口：

- `POST /data-assets:scan`：扫描批准的数据根目录并登记，不写原始文件。
- `POST /tasks/{task_id}/derive`：为未完成输入创建幂等计算计划和作业。

数据准备 CLI 负责大型空间处理；API 只调度或读取结果，避免 Web 请求长时间占用内存和 CPU。

## 8. 智能体计划与安全执行

### 8.1 计划顺序

每个输入节点按以下顺序处理：

1. 查询完全匹配的本地/官方事实。
2. 查询可直接聚合的派生观测。
3. 查询方法注册表中允许的模型估算路径。
4. 让 DeepSeek 在允许的方法集合内选择方案并生成解释。
5. 校验结构化计划的字段、单位、年份、区域和依赖完整性。
6. 由安全执行器运行方法并写入证据账本。
7. 若所有允许路径均不可执行，再生成具体的部门数据请求或业务判断事项。

### 8.2 计划约束

DeepSeek 返回的计划必须包含：目标字段、方法 ID/版本、输入观测 ID、转换步骤、参数来源、预期单位、风险理由和用户解释。安全执行器只接受方法注册表中已实现的操作，不执行模型生成的 Python、Shell、SQL 或 URL。

大模型故障时，确定性资产匹配和计算仍可运行；系统记录“解释生成失败”，不能把已成功计算的值改成数据缺口。

## 10. 状态与双闸门

### 10.1 输入状态

| 状态 | 含义 | Demo 试算 | 正式核算 |
|---|---|---|---|
| 自动采用 | 本地/官方直接事实或全部 A 级输入的确定性计算 | 允许 | 按现有审核规则 |
| 公开数据计算 | 公开栅格/气象经版本化代码计算 | 允许 | 需正式来源与方法审核 |
| 模型估算·已进入试算 | AEF 分类、代理变量或经验参数 | 允许 | 不允许直接进入 |
| 建议复核 | 质量门槛边缘、来源轻微差异或高影响参数 | 默认允许，显著标记 | 不允许直接进入 |
| 等待部门数据 | 工具已穷尽，确需经营或部门原始记录 | 保持缺口或使用明确选择的代理 | 阻断 |
| 需要业务判断 | 适用性、计量边界、去重或来源冲突 | 阻断相应路径 | 阻断 |
| 不适用候选 | 自动取得明确地理/业务证据 | 排除后可继续 | 需审核确认 |
| 执行失败 | 数据损坏、工具错误或网络故障 | 可重试，不伪装为缺口 | 阻断 |

科目节点不再排入补充队列。其状态由下游输入汇总，例如“7/8 已自动准备，1 项等待部门数据”。

### 10.2 就绪度

- `demo_ready`：允许使用自动采用、公开数据计算、模型估算和用户选择保留的建议复核值。
- `formal_ready`：只在正式边界、正式来源、方法版本和人工审核满足现有规则时成立。
- 页面可以展示 Demo 分项和总值，但标题必须为“智能试算”，并同时显示估算输入占比和正式阻断项数量。

## 11. 页面设计

### 11.1 数据准备页

页面增加“指标图 / 数据后台”两个子视图。

**指标图**：

- 根节点显示自动准备覆盖率、估算占比和人工事项数量。
- 科目节点显示下游完成度，不显示“已自动检索·等待数据”。
- 输入节点使用第 10 节状态；水流动画继续表示依赖方向，事件高亮表示新资产或新计算已落账。
- 右侧只保留一个主操作：等待自动计算、查看人工事项、整批确认估算或进入试算。

**数据后台**：

- 按来源、年份、类型、质量和使用指标筛选资产。
- 每个资产显示覆盖范围、SHA-256、许可、质量限制和已生成观测。
- 可查看 AEF 分类报告、栅格产物缩略图、MODIS/NASA 汇总和方法版本。

### 11.2 详情抽屉

顺序保持证据优先：

1. 当前结果与状态；
2. 数据来源和资产版本；
3. 自动校验与质量；
4. 计算过程：输入、公式、参数、单位转换和输出；
5. 不确定性与 Demo/正式适用范围；
6. 折叠的工具执行记录；
7. 必要时才显示人工动作。

人工事项按“部门/材料/一次决定”合并。一次确认去重规则应作用于相关多个节点，避免同一问题重复询问。

## 12. 错误处理与恢复

- 下载使用临时文件、Range 重试、大小/哈希检查和原子改名；中断后可继续，不把半成品登记为资产。
- AEF 瓦片重叠、边界空洞、NoData、方向和反量化错误都有独立质量检查。
- 资产、观测、计划和运行均使用幂等键；worker 重启不会重复写入候选。
- 输入资产或方法版本变化时，旧计算标记为 stale，不能静默覆盖人工修正。
- 数据质量未达门槛时降级为“建议复核”，不伪装成执行成功或正式输入。
- 正式结果与 Demo 结果使用不同字段和标题，任何导出均保留估算标记。

## 13. 安全与许可

- DeepSeek API 密钥继续只注入 worker，不进入 API、Web、SQLite 事件、日志、Git 或导出包。
- DeepSeek只接收结构化元数据、摘要和必要片段，不接收完整遥感文件。
- 官方网页发现允许扩展来源注册表，但只有 HTTPS、发布方身份、年份、区域、定位和许可验证通过后才能作为证据。
- AEF 输出保留 CC-BY 4.0 署名：“The AlphaEarth Foundations Satellite Embedding dataset is produced by Google and Google DeepMind.”
- WorldCover、MODIS、NASA POWER、Copernicus DEM 和在线来源分别保留原始许可和归属。
- 数据后台 API 不提供任意本地路径读取；只访问已登记资产 ID。

## 14. 测试策略

### 单元测试

- AEF index 选择、VRT 方向、NoData、反量化、重叠去重和边界裁剪。
- 资产/观测模式、哈希、单位、年份和区域验证。
- 方法计划 JSON Schema 和允许操作校验。
- R1、R2、R6、R7、R10 的确定性计算与单位转换。
- Demo/formal 双闸门和科目汇总状态。

### 数据质量测试

- AEF 覆盖率、波段数、分辨率、CRS、NoData 和输出哈希。
- WorldCover/AEF 对齐、空间块无泄漏、分类指标和面积勾稽。
- MODIS QC/有效像元、ET 完整期、NASA 月份完整性。
- 派生观测的有限数、单位范围、输入资产存在性和 lineage 完整性。

### 集成与浏览器测试

- 新建任务后资产扫描、计划、执行、落账和页面状态端到端运行。
- 22 个科目节点不进入 research-gap。
- 数据后台可筛选并查看计算链。
- 右侧主操作始终只有一个；人工事项合并展示。
- 刷新、worker 重启、版本冲突和失败重试不丢失记录。
- 真实浏览器无运行时错误，桌面与移动端无页面横向溢出；大型指标图只在画布内部滚动。

## 15. 首轮验收标准

1. 2024 AEF 海淀子集完成裁剪、哈希、质量报告和 CC-BY 署名。
2. AEF 分类器完成空间块验证并按门槛决定“自动试算”或“建议复核”。
3. 数据后台能查询 AEF、WorldCover、DEM、MODIS NPP/ET、NASA POWER 和已有官方事实。
4. R1、R6、R10 至少各形成一条可点击、可复算的完整自动计算链；R2 展示已自动生成的空间参数；R4 形成不适用候选。
5. 新任务中不存在 indicator 类型的 research-gap；科目显示下游完成度。
6. 页面区分自动采用、公开数据计算、模型估算、部门数据、业务判断、不适用和失败。
7. 智能试算可消费模型估算；正式核算继续阻断不合格输入。
8. 人工事项按一次材料或一次决定合并，不以 94 个字段按钮暴露给用户。
9. 所有新旧测试、数据质量检查和真实浏览器验收通过。
10. 部署前备份运行数据库，以不可变 release 发布到 9088；GitHub 保存独立提交和回退点。

## 16. 发布与回退

- 新功能由 `GEP_SMART_DATA_ENABLED` 控制；关闭时恢复现有研究流程和页面，不删除新表数据。
- 数据准备产物使用独立数据版本 `smart-data-2024-v1`，不会修改既有 `reference-2024-v0.1`。
- 旧任务不自动重写；用户选择“升级数据版本”时才克隆为新版任务并保留父任务 ID。
- 每个实施批次独立提交并同步 GitHub 功能分支；通过验收后合并 main。
- 宿主机每次升级前备份 SQLite，发布到独立 release 目录；健康、任务恢复、worker、数据质量或浏览器验收失败时切回上一 release 和对应备份。

## 17. 首轮实施顺序

1. 数据资产/观测模式、扫描 CLI 和查询 API。
2. AEF 2024 范围获取、裁剪、质量检查和分类器。
3. MODIS/NASA/DEM/WorldCover 观测生成器和首批方法实现。
4. 智能体结构化计划、安全执行与证据链。
5. 双闸门、科目汇总状态、数据后台和详情抽屉。
6. 迁移、端到端测试、宿主机数据同步、9088 部署和 GitHub 合并。

该顺序保证每个批次都能独立测试和回退，同时尽早形成一条真实的“数据资产 → 自动计算 → 页面解释 → 智能试算”垂直链路。
