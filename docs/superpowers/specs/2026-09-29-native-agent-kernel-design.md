# 海淀区 GEP 原生智能体内核设计规格

日期：2026-09-29

状态：已批准（2026-09-29）

目标版本：原生智能体第一阶段

## 1. 背景与目标

现有海淀区 GEP Demo 已具备任务图、异步 Worker、本地数据后台、空间分析工具、证据记录和 DeepSeek 直接调用能力，但当前补充流程仍是固定顺序工作流。它只能查询本地台账、预设官方来源和少量空间工具，不能主动完成通用互联网搜索、网页/PDF 阅读、知识库检索和多轮工具调用。因此部分节点过早进入“等待部门数据”或“人工介入”。

本次改造的目标是把现有固定工作流升级为一个项目自有的、可审计的 GEP 智能体系统，让智能体完成约 80% 的资料查找、证据整理、计算准备和过程说明，人工集中处理约 20% 的口径决策、来源冲突、授权数据和正式审核。

本设计遵循以下边界：

- 不部署 Dify，不把运行可靠性绑定到外部编排平台。
- 保留当前 Web、API、SQLite、Worker 和 Docker Compose 架构。
- DeepSeek 负责意图理解、检索规划、工具选择和中文说明，不直接制造事实或执行任意代码。
- 所有数值必须来自登记工具、可追溯证据或版本化计算方法。
- 智能试算和正式核算继续隔离；自动补充不能越过正式审核闸门。
- 第一阶段优先解决“能搜、能读、能存、能解释”，不引入复杂分布式基础设施。

## 2. 用户体验成功标准

### 2.1 面向首次使用者

用户点击一个指标节点后，右侧抽屉按“讲题”顺序显示：

1. 这一步在算什么；
2. 需要哪些输入数据；
3. 系统已经找到哪些数据；
4. 使用什么公式或方法；
5. 数值如何代入、单位如何转换；
6. 每一步得到什么中间结果；
7. 最终结果及其可用范围；
8. 系统搜索过哪些来源、仍缺什么；
9. 是否需要人工处理，以及人工只需处理什么。

界面字段使用“中文名称（程序字段）”格式，例如“生态系统面积（ecosystem_area）”。状态文案不得只显示 `pending`、`applicable` 等英文值。

### 2.2 自动化目标

- 已有本地或后台数据能够自动复用，不再次要求人工上传。
- 可公开检索的数据由智能体主动搜索、阅读、提取和校验。
- 可用已登记方法计算的数据由工具自动计算并留下完整步骤。
- 仅业务口径、授权受限、来源冲突和高风险正式采用需要人工介入。
- 多个同类缺口归并为一个人工工作包，避免逐字段重复审核。

## 3. 总体架构

```text
浏览器
  │
  ▼
Nginx :9088 ──► Python API ──► SQLite
                              任务 / 节点 / 作业 / 审核 / 证据
                                   ▲
                                   │
                              异步 Worker
                                   │
                            AgentKernel 智能体内核
                 ┌─────────────────┼──────────────────┐
                 ▼                 ▼                  ▼
          Planner 任务规划器   ToolRegistry 工具中心   Policy 策略闸门
                                   │
           ┌────────────┬──────────┼───────────┬────────────┐
           ▼            ▼          ▼           ▼            ▼
       本地数据检索   项目知识库   Web 搜索   网页/PDF读取   GEP/空间计算
           └────────────┴──────────┼───────────┴────────────┘
                                   ▼
                         EvidenceValidator 证据校验
                                   ▼
                          EvidenceLedger 证据台账
                                   ▼
                      候选值 / 计算过程 / 人工工作包
```

AgentKernel 作为 Worker 内部的新模块接入，不另建微服务。这样可以复用现有 SQLite 作业、重试、事件和部署机制，并保持单机 Demo 的运维复杂度可控。

## 4. 核心组件

### 4.1 AgentKernel（智能体内核）

职责：

- 接收当前任务节点、地区、年度、方法范围和已有证据；
- 生成受约束的检索与计算计划；
- 调用 ToolRegistry 中允许的工具；
- 根据工具结果决定继续检索、执行计算、形成候选或生成工作包；
- 输出结构化执行记录和面向用户的中文“讲题”说明。

内核使用有限状态循环，不采用开放式无限推理：

```text
PLAN → CALL_TOOL → OBSERVE → VALIDATE →
  ├─ 有充分证据：CALCULATE → EXPLAIN → COMPLETE
  ├─ 仍可检索：PLAN（进入下一轮）
  ├─ 来源冲突：REVIEW_REQUIRED
  └─ 无公开路径：HUMAN_WORK_PACKAGE
```

默认限制每个节点最多 8 次工具调用、3 轮计划、60 秒执行时间。达到限制后保留已取得的证据并生成明确的下一步，不返回含糊的“等待数据”。

### 4.2 Planner（任务规划器）

DeepSeek 输出结构化计划，不输出可直接执行的 Python、Shell、SQL 或任意 URL 请求。计划包含：

- 目标字段和中文名称；
- 所需输入及目标单位；
- 候选工具 ID；
- 检索关键词与来源类型；
- 允许的方法 ID/版本；
- 停止条件和风险关注点。

所有模型输出经过 JSON Schema 校验。无效计划仅重试一次；仍无效时转入确定性回退流程，不影响本地数据复用和已有计算。

### 4.3 ToolRegistry（工具注册中心）

每个工具使用统一协议：

```python
ToolSpec(
    tool_id: str,
    title_zh: str,
    description: str,
    input_schema: dict,
    output_schema: dict,
    risk_level: str,
    network_access: bool,
)

ToolResult(
    status: str,
    data: dict,
    evidence: list[dict],
    warnings: list[str],
    elapsed_ms: int,
)
```

首批工具：

| 工具 ID | 作用 | 首阶段实现 |
|---|---|---|
| `local.catalog.search` | 查询本地数据台账和准入文件 | 复用 `EvidenceCatalog` |
| `smart.observation.search` | 查询后台派生观测 | 复用 `SmartDataStore` |
| `official.registry.search` | 查询预设官方来源 | 复用 `OfficialSourceRegistry` |
| `web.search` | 通用互联网搜索 | 可插拔搜索适配器 |
| `web.read` | 提取网页正文和元数据 | 新增安全读取器 |
| `document.read` | 读取 PDF/文档指定页 | 新增文档读取器 |
| `knowledge.search` | 检索标准、方法和已采纳证据 | 新增 SQLite FTS5 知识库 |
| `geo.alphaearth.inspect` | AlphaEarth 数据检查和空间结果 | 复用 `AefSpatialTool` |
| `gep.method.execute` | 执行已登记 GEP 方法 | 复用公式与方法注册表 |
| `evidence.validate` | 校验地区、年份、单位、来源和冲突 | 新增统一校验器 |

工具只能由注册表实例化。模型不得临时发明工具、访问文件路径或执行代码。

### 4.4 WebSearch（互联网搜索）

采用适配器接口，业务层不绑定单一搜索供应商：

```python
class SearchProvider:
    def search(self, query, *, domains=None, limit=5, language="zh-CN") -> list[SearchHit]: ...
```

搜索优先级：

1. 政府和权威机构域名定向搜索；
2. 配置的结构化搜索服务；
3. 自建 SearXNG（可选）；
4. 无凭据的公开搜索适配器，仅作为发现线索。

第一阶段至少实现一个无新增密钥即可运行的搜索适配器，并保留 Tavily、Serper 或 SearXNG 的配置入口。搜索结果本身不是证据，必须由 `web.read` 读取原页面后才能进入证据校验。

### 4.5 KnowledgeBase（项目知识库）

第一阶段使用 SQLite FTS5，不引入独立向量数据库。知识库内容包括：

- GB/T 46869-2025 的允许摘录与页码定位；
- 项目方法说明、字段定义、单位和中文名称；
- 已验证的官方网页和公开报告；
- 已采用数据的证据摘要；
- 历史任务中经审核通过的口径决策。

每条知识记录必须包含来源、定位、内容哈希、获取时间、适用地区、适用年度、许可证/访问条件和审核状态。未审核互联网内容可以参与检索，但不能自动升级为正式证据。

如后续中文语义检索质量不足，再增加本地向量索引；第一阶段不提前引入该复杂度。

### 4.6 EvidenceValidator（证据校验器）

校验维度：

- 来源等级：政府/标准、权威公共数据、论文、一般网页；
- 地区匹配：海淀区、北京市、可迁移区域或无区域；
- 时间匹配：目标年度、临近年度或历史参数；
- 指标口径：字段含义、统计范围和空间范围；
- 单位：原单位、转换公式和目标单位；
- 完整性：URL、标题、发布者、定位、哈希、抓取时间；
- 冲突：同一口径多个数值是否一致；
- 新鲜度：价格、政策和年度统计是否过期。

风险分级：

| 等级 | 条件 | 自动化行为 |
|---|---|---|
| A | 本地准入事实或完全匹配的正式观测 | 可自动采用并留痕 |
| B | 官方公开值或确定性公开数据计算 | 可进入智能试算；正式结果按现有规则审核 |
| C | 论文参数、跨区域代理或模型估算 | 自动完成试算，但明确标记假设和风险 |
| D | 来源冲突、授权受限、关键业务口径 | 归并为人工工作包 |

### 4.7 EvidenceLedger（证据台账）

在现有数据库中增加：

- `agent_runs`：一次智能体运行的目标、状态、预算、耗时和模型版本；
- `tool_runs`：每次工具调用的输入摘要、结果摘要、错误和耗时；
- `evidence_items`：来源、定位、哈希、内容片段、适用范围和风险；
- `calculation_steps`：公式、输入引用、单位转换、中间值和结果；
- `knowledge_documents`：知识库文档元数据；
- `knowledge_chunks_fts`：FTS5 检索内容；
- `agent_decisions`：自动采用、试算、冲突或人工工作包的理由。

敏感凭据、完整网页正文和模型隐藏推理不进入台账。台账记录可审计的操作与理由，而不是内部思维过程。

## 5. 数据流

一个节点的标准流程：

1. `SmartDataWorkflow` 查询完全匹配的后台观测；
2. AgentKernel 查询本地目录和知识库；
3. 若证据不足，Planner 生成定向 Web 搜索计划；
4. `web.search` 返回候选页面；
5. `web.read` 或 `document.read` 读取原始内容；
6. EvidenceValidator 校验地区、年度、单位、口径和来源；
7. 若方法输入齐全，`gep.method.execute` 执行计算；
8. 计算过程和证据写入 EvidenceLedger；
9. DeepSeek 基于已验证的结构化结果生成中文讲解；
10. 结果进入智能试算，或按风险规则进入人工工作包。

DeepSeek 不得修改工具返回的数值。说明中的数字由模板从结构化结果注入，防止解释文本与计算结果不一致。

## 6. 右侧抽屉信息设计

节点抽屉固定为以下模块：

1. **核算对象**：中文指标名（程序字段）、单位、当前结果；
2. **本步目标**：一句话解释这一步解决什么问题；
3. **所需输入**：逐项显示中文名（字段名）、数值、单位、年份和来源状态；
4. **计算方法**：中文方法名（方法 ID）、适用范围和选用理由；
5. **代入与计算**：公式、代入值、单位换算和中间结果；
6. **结果怎么理解**：当前值代表什么、是否仅适用于 Demo；
7. **数据来源**：来源标题、发布者、年份、定位和可访问链接；
8. **工作执行记录**：搜索、读取、校验、计算等可折叠时间线；
9. **风险与人工事项**：只列真正需要人工处理的事项；
10. **审核操作**：单项审核和整批确认。

“智能体如何补充”不作为页面标题。用户看到的是结果、来源、过程和剩余工作，而不是内部技术术语。

## 7. 安全与失败处理

### 7.1 网络安全

- 只允许 `http`/`https`，默认拒绝本机、内网、链路本地和云元数据地址；
- DNS 解析后再次校验目标地址，防止 SSRF 和重绑定；
- 限制响应体大小、超时、重定向次数和内容类型；
- 不执行网页脚本，不接受网页内容中的操作指令；
- 搜索或网页内容视为不可信数据，不作为系统提示词。

### 7.2 凭据安全

- DeepSeek 和搜索服务密钥只注入 Worker；
- 密钥不写入数据库、日志、前端、Git 或证据台账；
- 工具日志对请求头和敏感查询参数脱敏；
- 继续使用主机受限环境文件注入凭据。

### 7.3 故障降级

- 搜索供应商失败：切换下一适配器；
- 网页不可读：保留搜索线索但不形成证据；
- DeepSeek 失败：继续执行确定性本地查询和计算，说明使用模板生成；
- 单个工具失败：记录错误并允许规划器选择替代工具；
- 达到预算：输出已取得结果和具体缺口，不回滚成功证据；
- 来源冲突：禁止自动选择，转为一个冲突复核工作包。

## 8. 测试策略

实现过程采用测试驱动开发。

### 8.1 单元测试

- 工具注册、Schema 校验和未知工具拒绝；
- AgentKernel 状态转换、调用次数和超时预算；
- Web 搜索适配器结果归一化；
- 网页读取器的 SSRF、重定向、大小和类型限制；
- FTS5 知识库写入、检索、哈希和审核状态；
- 证据地区/年度/单位匹配与冲突识别；
- 计算步骤数字与讲解文本一致；
- DeepSeek 故障时的确定性降级。

### 8.2 集成测试

- 用本地 HTTP 测试站模拟搜索结果、HTML、PDF、重定向和失败页面；
- 从节点任务到工具调用、证据入库、计算和候选结果的完整链路；
- Worker 重试不重复写入证据和计算步骤；
- 旧任务和现有 SmartDataWorkflow 保持兼容。

### 8.3 浏览器验收

- 抽屉完整显示“算什么—输入—公式—代入—结果—来源—风险”；
- 中文名称优先，英文程序字段仅在括号中出现；
- 工作执行记录可展开；
- 不再出现无法解释的“已自动检索等待数据”；
- 整批确认能够提示未审核项并按用户选择继续或返回逐项审核。

## 9. 分阶段交付与 Git 回退点

每个阶段独立测试、提交并推送 GitHub：

1. **设计规格**：本文件，确定边界和接口；
2. **智能体基础骨架**：ToolRegistry、类型、AgentKernel 状态机和数据库迁移；
3. **知识库**：SQLite FTS5、文档导入和检索；
4. **Web 工具**：搜索适配器、安全网页/PDF 读取；
5. **证据与计算闭环**：统一校验、台账和方法执行；
6. **Worker 接入**：把固定 ResearchWorkflow 迁移到智能体内核并保留回退开关；
7. **抽屉改版**：中文讲题式计算过程与工作记录；
8. **数据回填与验收**：用海淀 Demo 真实数据跑通、浏览器检查、部署到 9088。

每一阶段推送后记录提交 SHA。线上切换前保留 `GEP_AGENT_ENABLED=0` 回退开关；关闭后继续使用当前 SmartDataWorkflow 和 ResearchWorkflow。

## 10. 不在第一阶段范围内

- 不部署 Dify、LangChain、独立向量数据库或 Kubernetes；
- 不允许模型执行任意 Python、Shell、SQL；
- 不自动绕过登录、验证码、付费墙或数据授权；
- 不把论文或普通网页参数直接升级为正式核算依据；
- 不在首轮实现多智能体分布式协作；
- 不替代最终核算责任人的正式审核。

## 11. 验收条件

第一阶段完成时必须满足：

- 9088 页面仍可访问，现有任务和数据不丢失；
- 至少一个缺失节点能完成“Web 搜索—原文读取—证据校验—知识入库—方法计算—中文讲解”；
- 至少一个本地观测节点无须联网即可自动完成；
- 至少一个来源冲突案例正确进入归并人工工作包；
- 所有数值能追溯到证据项和计算步骤；
- DeepSeek 或搜索服务不可用时，系统能够降级而不是整体失败；
- 凭据不进入 Git、SQLite、日志或前端响应；
- 自动化测试、空间测试和浏览器验收全部通过；
- 每一阶段均有已推送的 Git 提交，可按 SHA 回退。
